I've been building in public for over a year, and I'd never looked at my own GitHub the way someone deciding whether to hire me would. Last week I did. I gave myself a C+.

None of it was about code quality. It was about what a stranger can see in the two minutes they'll give it.

## What a stranger actually sees

A hiring manager or a potential client opens your profile, reads the pinned repos, maybe opens one README, and leaves. So I checked exactly that path and nothing else.

What I found:

- **Three of my six pinned repos were archived.** Pins are the storefront. I was leading with finished experiments instead of current work.
- **No pin showed the work I want to be hired for.** My strongest professional work is contact center automation, and none of it was visible from the profile.
- **My profile README linked to a repo that returns a 404** to anyone but me, because that repo is private now.
- **Four public repos had descriptions that literally said "No README yet".** One of them is a model router I'd described in bigger terms than its code justified.
- **My name was different in two places.** Small, but it looks like two people.
- **Flagship repo roots were cluttered** with scratch files and folders that made the real entry points hard to find.
- **One README flagged its own sections as stale.** Honest, but not a great first impression.

## The README test

For each public repo without a README, I had a draft written from the code, not from my old descriptions. That turned out to matter. One description promised fallbacks and pricing that the code didn't have. A README that matches the code is worth more than one that matches my plans.

A good small README answers four things on the first screen:

1. What this does, in one sentence.
2. How to run it.
3. What state it's in (active, finished, retired).
4. What I'd point a reader at first.

That's it. A short true README beats a long aspirational one.

## The pins, rethought

I changed the pins to lead with work that represents what I do now: my game, my public method write-up, the game studio, and my tooling for agents and git. The archived experiments are still there for anyone who digs; they just aren't the front door. The next step is a clean public copy of the agent harness I'm retiring, which is the project I most want people to see.

## The question to ask yourself

Open your profile in a private browser window, logged out, and give it two minutes. If the first thing you see isn't the work you want to be known for, that's the fix, and it's usually an afternoon of README writing and pin shuffling, not new code.
